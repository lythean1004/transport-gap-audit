# 2차 감사(보완 감사) 리포트

## [H] 수정 판정표

| 항목 | 판정 | 근거 |
|---|---|---|
| 스키마 일치 | UNVERIFIED | 스키마 버전 다수 혼재 또는 1차 미검증 항목 |
| 평일 3일 이상 확보 | PASS | 유효 분석 대상 3일 확보 |
| 커버리지 기준 | PASS | 분석 대상 일자 커버리지: 2026-09-07(91.7%), 2026-09-08(100.0%), 2026-09-09(100.0%) |

| BUDGET_STOP 없음 | PASS | BUDGET_STOP 0건 발생 |

| 유효 관측치 정의 | WARN | ok_empty 2건 중 배차공백 2건, API결측 0건 |
| 판정 근거 하드코딩 없음 | PASS | 자체 검증 결과, f-string으로 동적 생성됨 |

## 1차 감사 대비 변경된 판정 목록과 각 변경 사유

1. **커버리지 기준**: FAIL -> PASS
   - 사유: 스케줄러 오류로 소실된 셰이크다운일(9/4)과 현재 미완료일(9/10)을 배제 규칙에 따라 분석 창에서 제외한 결과, 남은 유효 분석일(9/7, 9/8, 9/9) 모두 90% 이상의 커버리지를 달성함.
2. **드리프트**: (신규 FAIL 명시) -> FAIL
   - 사유: 정규 호출(retry=0)만을 분리하여 측정한 결과, p95=7.32초, max=134.66초로 나타나 '정규 호출이 전수 1~4초 이내'라는 명제가 거짓으로 판명됨.
3. **TRUNCATED**: (미검증) -> PASS
   - 사유: 모든 응답 JSON 원본에 대해 `totalCount`와 실제 `items` 배열의 길이를 대조한 결과, 누락(Truncated) 현상이 한 건도 없음을 확인함.
4. **키 중복 없음**: PASS -> WARN
   - 사유: 120초 이내에 호출된 준중복 관측이 2쌍 발견되었으며, 이 중 일부는 서로 다른 슬롯에 대해 실행되어 실효 독립 관측치가 아닌 것으로 판정됨.
5. **유효 관측치 정의**: (미검증) -> WARN
   - 사유: `ok_empty`로 기록된 2건의 응답 원문을 분석한 결과, API 에러가 아닌 "실제 배차 공백 가능성"(resultCode: 00, totalCount: 0)으로 확인됨.

## 논문에 인용하면 안 되는 1차 보고 수치 목록

- **1차 보고 item_count 전체/오전/오후 평균 수치**: 해당 평균(오전 25.68 / 오후 23.35)은 통신 실패(`api_error`)로 아이템 개수가 없는(NaN/0 처리) 비정상 행까지 포함하여 단순 계산된 오염된 통계량임. 정규 응답(`ok_with_items`) 기준으로 다시 산출한 값을 사용해야 함 (전체: 25.05).
- **드리프트 최대치 (304.83초)**: 이는 재시도 로직(`sweep`)에 의해 과거 슬롯이 뒤늦게 실행된 결과가 섞여 들어간 수치이며, 순수 스케줄러 트리거에 의한 자연 드리프트(최대 134.67초)와 구별해야 함.
- **단순 일자별 명목 슬롯 수**: 준중복 호출과 중복 슬롯 관측을 제외한 **실효 독립 슬롯 수**(예: 9/7은 44개)로 정제하여 인용해야 함.

## 확인불가 / UNVERIFIED 항목 전체 목록

- **스키마 일치 여부**: 1차 감사 시 누락된 항목이거나 과거 버전의 데이터 혼재 등 무결성 확보 근거가 부족하여 현재로서는 확인할 수 없음(UNVERIFIED).
- **결측 슬롯 발생의 구체적 원인 단정**: 로그 기록 미비 및 인스턴스 중첩 등 여러 후보(절전 모드 등)가 있으나, 현재 수집된 `_task_log.txt`와 원장 데이터만으로는 특정 원인을 100% 확정하여 단정할 수 없음.

## 다음 단계에서 사람이 결정해야 할 사항 3가지

1. **`ok_empty` 현상의 해석 및 처리 방안**: 저녁 피크 시간대에 13개 노선이 지나가는 정류장에서 `totalCount: 0`인 응답이 발생한 것(2건)을 실제 배차 공백(관측 데이터의 일환)으로 수용할 것인지, 아니면 API 제공 측의 일시적 오류 아티팩트로 간주하여 결측 처리할 것인지 결정.
2. **드리프트 지연 현상 수용 여부**: 정규 호출에서조차 드리프트가 최대 134초 이상 지연 발생하는 현상이 관측 데이터의 시간적 정밀도 요구사항을 훼손하는지 판단하고, 허용 범위를 넘는다면 개선안 도입 결정.
3. **준중복 관측 및 스케줄러 간섭 문제**: 과거 슬롯이 뒤늦게 처리되면서 실효 독립성이 떨어지는 준중복 관측이 발생하는 구조적 문제를 해결하기 위한 스케줄러 조정이나 프로세스 동시성 통제 여부 결정.
